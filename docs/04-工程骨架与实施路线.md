**分层约定（每个服务一致，禁止跨层）**

```
api/       对外接口层：Controller + Request/Response。只做参数解析与结果包装，不写业务
app/       应用层：用例编排。事务、状态机、跨服务调用都在这里
domain/    领域层：实体、枚举、状态机、仓储接口
infra/     基础设施层：persistence / client / mq / cache / storage / security
config/    Spring 配置
```

## 2. 骨架中已落实的关键设计（可直接评审）

| # | 设计点 | 落地位置 |
|---|---|---|
| 1 | 统一返回、错误码分段、全局异常 | `rag-common/core`、`rag-common/exception` |
| 2 | 请求上下文 + traceId + MDC 贯穿 | `RequestContextFilter` + `TracePropagationInterceptor` |
| 3 | 雪花 ID → JSON 字符串（防前端精度丢失） | `RagCommonJacksonAutoConfiguration` |
| 4 | 网关洗白客户端可伪造头 + 注入来源标识 | `RequestSourceSanitizeGlobalFilter` |
| 5 | 两套鉴权分流唯一入口 | `SourceAuthInterceptor`（rag-api，5 服务复用） |
| 6 | 防伪造三道闸（网关洗白 / 来源校验 / 反向拦截） | 同上 + `REQUEST_SOURCE_FORGED` |
| 7 | 应用签名（HMAC-SHA256 + 时间窗 + nonce + IP 白名单 + 常量时间比较） | `AppSignatureVerifier`、`HmacSignatures`、`NonceReplayGuard` |
| 8 | 敏感字段落库加密（AES-256-GCM） | `AesCiphers` |
| 9 | 越权防护授权真源 | `AuthorizedKbQueryAppService` |
| 10 | 检索结果二次过滤（密级/生效期/跨库/去重） | `ChunkBusinessFilter` |
| 11 | 缓存 Key 必须含权限与版本指纹 | `RetrievalCacheKeyBuilder` |
| 12 | 文档解析状态机 + 超时兜底 | `IngestTask.Status`、`ParseStatusPollingJob` |
| 13 | 本地消息表（Outbox）保证「写库 + 通知下游」一致 | `OutboxMessage`、`OutboxRelayJob` |
| 14 | 模型按密级动态路由 | `LlmRouter` |
| 15 | 「无据不答」+ 引用完整性 + 数值无引用告警 + 敏感脱敏 | `AnswerGuardrail`、`ChatOrchestrationAppService` |

| # | 风险 | 说明 | 处置 |

## 5. 本地联调：快速开始

### 5.1 依赖中间件（docker-compose 参考）

```yaml
# docker-compose-infra.yml —— 仅用于本地联调，生产请按 HA 方案部署
services:
  mysql:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: root123
      MYSQL_DATABASE: rag_platform
    ports: ["3306:3306"]
  redis:
    image: redis:7-alpine
    command: ["redis-server", "--requirepass", "redis123"]
    ports: ["6379:6379"]
  minio:
    image: minio/minio
    command: server /data --console-address ":9001"
    environment:
      MINIO_ROOT_USER: minioadmin
      MINIO_ROOT_PASSWORD: minioadmin
    ports: ["9000:9000", "9001:9001"]
  nacos:
    image: nacos/nacos-server:v2.4.3
    environment:
      MODE: standalone
      MYSQL_SERVICE_HOST: mysql
    ports: ["8848:8848", "9848:9848"]
```

建库（4 个逻辑库）：

```sql
CREATE DATABASE rag_platform  DEFAULT CHARSET utf8mb4;
CREATE DATABASE rag_knowledge DEFAULT CHARSET utf8mb4;
CREATE DATABASE rag_ingest    DEFAULT CHARSET utf8mb4;
CREATE DATABASE rag_retrieval DEFAULT CHARSET utf8mb4;
CREATE DATABASE rag_chat      DEFAULT CHARSET utf8mb4;
```
表结构 DDL 见 **文档 03 §2–§6**，逐库执行。

RAGFlow 按官方 `docker/docker-compose.yml` 启动，注意先执行：

```bash
sudo sysctl -w vm.max_map_count=262144
```

### 5.2 启动前必须准备的环境变量

```bash
export RAG_AES_KEY=$(openssl rand -base64 32)   # AES-256 主密钥，32 字节
export RAG_JWT_SECRET=$(openssl rand -base64 48) # ≥32 字节
export RAGFLOW_API_KEY=ragflow-xxxxxxxx
export MINIO_ACCESS_KEY=minioadmin
export MINIO_SECRET_KEY=minioadmin
export RAG_GATEWAY_SIGN_SECRET=$(openssl rand -hex 32)  # 可选，启用网关签名强校验时
```

> **纪律**：以上密钥一律不得写进 `application.yml` 提交仓库，只允许环境变量或配置中心加密配置。

### 5.3 Nacos 配置

在 Nacos 中按服务名创建 DataId（`group=RAG_GROUP`，`namespace=rag`）：

| DataId | 内容 |
|---|---|
| `rag-common.yaml` | 各服务公共配置（日志格式、actuator、脱敏公共项） |
| `rag-gateway.yaml` | 网关专属（公网路径白名单、限流阈值） |
| `rag-platform-service.yaml` | AES/JWT 密钥引用、网段白名单 |
| `rag-knowledge-service.yaml` | RAGFlow 地址与 Key |
| `rag-ingest-service.yaml` | MinIO、上传限制、轮询间隔 |
| `rag-retrieval-service.yaml` | 检索默认参数（阈值/权重/topN） |
| `rag-chat-service.yaml` | Prompt 版本开关、模型刷新间隔 |

### 5.4 构建与启动

```bash
# 全量构建
mvn -T 1C clean install -DskipTests

# 单个服务及其依赖
mvn -pl rag-chat-service -am clean package -DskipTests
java -jar rag-chat-service/target/rag-chat-service.jar
```

启动顺序：

```
MySQL / Redis / Nacos / MinIO / RAGFlow
  → rag-platform-service   （被所有服务依赖，必须最先起）
  → rag-knowledge-service
  → rag-ingest-service
  → rag-retrieval-service
  → rag-chat-service
  → rag-gateway
```

## 6. 编码规范约束（建议写入团队规约）

| # | 规则 | 原因 |
|---|---|---|
| 1 | 所有对外接口返回 `R<T>`，禁止裸对象 | 错误码与 traceId 要统一 |
| 2 | 业务异常用 `BizException`，禁止 `throw new RuntimeException("...")` | 错误码可观测 |
| 3 | 事务只包本地库，禁止把 RAGFlow / LLM / MinIO 调用放进 `@Transactional` | 长事务会拖垮连接池 |
| 4 | 跨服务调用必须显式声明超时，鉴权类 ≤ 500ms | 防止级联雪崩 |
| 5 | `datasetIds` 只能来自服务端推导，禁止使用请求体传入值 | 越权防护 |
| 6 | 缓存 Key 必须用 `RetrievalCacheKeyBuilder`，禁止手写 | 少一个维度就是越权 |
| 7 | 外部系统调用一律有「状态 + 重试 + 人工兜底」，禁止裸重试 | 分布式一致性 |
| 8 | 密钥/JWT/AES Key 只走环境变量或配置中心加密项 | 合规 |
| 9 | 内网 Feign 客户端禁止添加 `X-Request-Source` | 会被判为伪造并 403 |
| 10 | 引入 `rag-api` 的业务方需设 `rag.server.auth.enabled=false`（默认已关） | 避免把服务端拦截器装到业务方自己的接口上 |
